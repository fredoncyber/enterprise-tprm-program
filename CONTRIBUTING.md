# Contributing

1. Open an issue describing the control, template or methodology change.
2. Cite authoritative sources and distinguish requirements from guidance.
3. Avoid vendor endorsements and unsupported claims.
4. Never commit confidential vendor evidence, credentials, personal data or proprietary assurance reports.
5. Update mappings and tests when changing scoring logic.
6. Use pull-request review by at least one TPRM/security reviewer and one affected domain owner.
